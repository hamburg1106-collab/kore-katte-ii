# これ買っていい

1人用の資金管理PWA。「今これを買っていいか」に1秒で答えるためのもの。

収入・固定費・資産・ライフイベントを登録すると、**月にいくらまでなら使っても破綻しないか**を計算する。

## 実額はこのリポジトリに入っていない

GitHub Pagesの無料プランは公開リポジトリしか使えず、**ビルド後のJSにも値がそのまま残る**。
手取り・資産残高・契約先をコードに置くと、公開した瞬間に誰でも読める。

だから金額と固有名詞は全部 `seed.local.json`（`.gitignore` 済み・手元にしかない）に置き、
設定画面の「初期データの取り込み」から1回だけ貼り付ける。以後はFirestoreにあるので再入力はいらない。

`seed.local.json` の形は `src/lib/seed.ts` の `Seed` 型を見ること。設定画面の
「いまの内容を書き出す」で、現在の中身を同じ形で取り出せる（バックアップ用）。

## 動かす

```
npm install
npm run dev        # 開発サーバ
npm run build      # dist/ を作る
npm run icons      # public/ のアイコンを作り直す
npm run lint
```

## 公開する前にやること

1. **FirebaseコンソールでGoogleログインを有効にする**
   Authentication → Sign-in method → Google。
   さらに Authentication → 設定 → 承認済みドメインに公開先のドメインを追加する。
   忘れると `auth/unauthorized-domain` でログインが弾かれる。

2. **Firestoreのルールを貼る**
   `firestore.rules` を参照。**プロジェクトは他のアプリと共用しているので、
   既存のコレクションを消さないこと。**

3. **公開後、ビルド成果物に実額が混ざっていないか確かめる**
   ```
   npm run build
   # dist/assets/*.js を手元の数字で検索して、何も出ないこと
   ```

## 設計で外してはいけないところ

### 支出と資金移動を型で分ける

貯蓄型保険や積立投資は `kind: 'transfer'`。財布からは出ていくが、資産としては減っていない。
これを `expense` にすると、アプリは毎月その分だけ「あなたは貧しい」と言い続ける。

### ボーナスは月の生活費に混ぜない

月給ベースで恒常余力を出し、ボーナスはライフイベント引当と投資に全振りする。
長期の借入を抱えた状態で生活水準をボーナス前提に上げると、減った年に赤字が固定化する。

### 積立投資への一括投入は調整弁

期日を動かせるのは投資だけ。入学金も車検も時期はこちらで選べない。
だから引当を先に確保して、余った分を投資へ回す。逆にすると必ず破綻する。

### 発生主義で記録し、残高は別に持つ

支出は「使った日」で記録する（今月いくら使えるかを出すため）。
口座残高との照合は「実質残高 = 口座残高 − カード未確定分」で行う。
片方だけだと必ずどこかで嘘をつく。

### 生活防衛費の分母は「止められない支出」

失職したら投資の積立も貯蓄型保険もサブスクも止められる。止まらないものだけを6倍する。
出ていく額の全部を6倍すると下限が過大になり、「使っていい額」が不当に渋く出る。

## 意図的に作らないもの

- カテゴリ分類（裁量支出を10分割しても判断材料にならない）
- レシート撮影・AI解析（月10〜20件の記録に対して過剰）
- 同居家族の家計そのものの可視化
- 電子マネー残高の資産計上（オートチャージの誤差は月末の残高照合で吸収する）
- 銀行・カードのAPI連携

機能追加を考えるときは、まずここと照合する。
